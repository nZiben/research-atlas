# Настройки, импорт и эксплуатация

## Модели и ключи

В `review.toml` заполняются идентификатор модели и точный endpoint; секрет передаётся только через переменную окружения, указанную в `api_key_env`. Пример структуры (поля провайдера намеренно пусты до вашей настройки):

```toml
[model]
endpoint = ""
name = ""
api_key_env = "REVIEW_API_KEY"
require_api_key = true
json_mode = true
token_parameter = "max_completion_tokens"
max_output_tokens = 6000
```

API должен принимать `POST` с `model` и `messages`, возвращать `choices[0].message.content` как строку JSON и `finish_reason = "stop"`. Параметры сверены с [официальным Chat Completions API](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create). Совместимость конкретного стороннего endpoint надо проверить отдельно, когда будете готовы к реальному запуску.

Для провайдера, использующего `max_tokens`, явно поменяйте `token_parameter`. Для endpoint без `response_format` поставьте `json_mode = false`; требование к валидному JSON в ответе сохранится. `temperature` необязателен и по умолчанию не передаётся. Нет автоматической подмены модели или fallback на другой платный сервис.

Для второго endpoint раскомментируйте `[synthesis_model]` и полностью заполните его параметры. Он используется для синтеза и критики; поиск запросов, screening и extraction используют `[model]`. Общий лимит вызовов разделяется обеими моделями.

Для локального сервера HTTP разрешён только на `localhost`, `127.0.0.1` или `::1`. Проверка TLS для внешнего HTTPS не отключается. URL с паролями, токенами в query или userinfo не допускаются. Автоматические редиректы модельного API запрещены, чтобы не переслать ключ другому host.

Ключ Semantic Scholar необязателен: `SEMANTIC_SCHOLAR_API_KEY`. Его отсутствие не гарантирует доступность keyless API; 429/403/прочие ошибки честно сохраняются. arXiv GET-запросы внутри команды разнесены минимум на 3.1 секунды согласно [руководству API](https://github.com/arXiv/arxiv-docs/blob/develop/source/help/api/user-manual.md). Формат Semantic Scholar сверялся с [официальной документацией](https://api.semanticscholar.org/api-docs/snippets).

API-параметры и промпты не содержат ключей, но сохраняют отправленные тексты. `model_responses/` хранит фактические тела успешных HTTP-ответов, включая не прошедшие содержательную проверку ответы. Не отправляйте эти папки в публичные репозитории. Облачный API получает фрагменты источников; для чувствительных материалов используйте подходящий локальный endpoint или иной разрешённый режим обработки.

## Ручной импорт

`examples/manual-import.template.json` содержит пустой массив, который нужно заполнить **реальными** записями. Контракт одной записи:

| Поле | Формат | Требование |
|---|---|---|
| `title` | строка | Обязательно, непустое |
| `authors` | массив строк | Рекомендуется |
| `year` | целое число | Для отбора по дате; неизвестный год по умолчанию исключается |
| `url` | URL первоисточника | Нужен, если нет `local_path` |
| `doi` | строка | Если известен |
| `arxiv_id` | ID, желательно с версией | Если известен; например, форма `YYMM.NNNNNvN` |
| `pdf_url` | URL прямого PDF | Для автоматического чтения удалённой статьи |
| `local_path` | путь `.pdf`, `.md` или `.txt` | Относительно файла импорта либо абсолютный |
| `abstract` | строка | Для screening, особенно если нет онлайн-метаданных |
| `license` | строка | Только фактически известная; иначе `unknown` |

Не добавляйте выдуманную аннотацию при её отсутствии. Screening может опираться на неполные метаданные и ошибаться; решение о включении можно принять вручную. HTML URL страницы статьи без `pdf_url` не считается автоматически прочитанным полным текстом.

```bash
python -m review_forge import --project library/my-topic ./my-papers.json
python -m review_forge screen --project library/my-topic
```

Если у вас только набор локальных PDF, сначала создайте реальные библиографические записи с путями к ним. Проект не угадывает название, авторов и год из имени PDF и не заполняет пропуски выдумками.

Для исправления библиографии измените импортный файл и повторите import. Для более тонкой ручной коррекции можно отредактировать локальные кандидаты, затем повторить screen; прежние снимки сохранят старые данные.

## Источники и покрытие

Для arXiv перед чтением разрешается точная версия через Atom API; документ сохраняет фактически полученный ID. Если lookup временно недоступен, допускается уже известный versioned ID. Неверсионированная запись без разрешённой версии блокируется. Для остальных источников фиксируются URL, дата получения и SHA-256 фактически скачанного файла; неизвестная версия не объявляется известной.

PDF читается через [`pypdf.PdfReader`](https://pypdf.readthedocs.io/en/stable/modules/PdfReader.html), страницы — через `extract_text()`. [Документация pypdf](https://pypdf.readthedocs.io/en/stable/user/extract-text.html) отдельно объясняет ограничения извлечения и отличие от OCR. Число символов — грубый фильтр пустого документа; наличие текста не доказывает полноту и правильный порядок чтения. Скан без текстового слоя требует внешнего OCR и осознанно подготовленного импорта.

При явно включённом `allow_abstract_only` неудачная загрузка или слишком короткая экстракция может дать карточку только по аннотации. Причина и ограничение сохраняются. Этот режим подходит для предварительного каталога; глубокие выводы о методах требуют полного источника.

Исходники в `corpus/` и полные сегменты в snapshot остаются приватными. Выходной HTML/Markdown имеет бюджет показываемых цитат на статью. Выходной JSON содержит все короткие цитаты извлечённых тезисов — этот бюджет не является автоматической правовой проверкой.

## Бюджеты и продолжение

- `max_model_calls`: верхняя граница сетевых обращений модели **за одну команду**, включая неудачные попытки. При новом запуске начинается новый лимит; общий расход смотрите по `runs/` и кабинету провайдера.
- `max_output_tokens`: запрашиваемый предел вывода/рассуждения согласно конкретному API. Слишком маленький предел часто даёт `finish_reason=length`; такой ответ отвергается.
- `max_input_chars`: предел сериализованных сообщений. Символы не равны токенам; подберите под фактическое context window. Ни текст, ни список источников автоматически не обрезаются ради прохождения лимита.
- `max_candidates`: предел кандидатов для модельного screening. Превышение требует сузить поиск, задать явные исключения или поднять лимит.
- `max_papers`: предел включённых статей. Остальные релевантные работы получают `deferred`, а не исчезают из журнала.
- `synthesis_claims_per_paper`: ограничение компрессии доказательств для общего синтеза; выбранные ID и причина хранятся в карточке.
- `min_papers`: минимум основных работ. Внешние работы не засчитываются в этот минимум.

Точной оценки стоимости в долларах нет: тарифы, длины источников, reasoning tokens и провайдер не известны. Usage сохраняется как сообщает API; отсутствующие значения не подменяются нулями. До большого запуска проверьте тариф и оцените число страниц/частей.

GET-запросы имеют ограниченные повторы с задержкой; POST модели не повторяется автоматически. После таймаута она могла уже обработать запрос. Результат такой попытки не считается успешным, а запись о попытке остаётся в `model_requests/` и `runs/`. Незавершённый текущий платный запрос не всегда можно безопасно восстановить; завершённые проверенные части переиспользуются.

Блокировка файла `.lock` действует на одну тему и автоматически освобождается после завершения процесса. Одновременно можно читать готовый экспорт другой программой. Параллельный запуск многих тем на одном API требует отдельного глобального rate limiter; он сейчас не реализован.

## Частые остановки

| Сообщение/ситуация | Что сделать |
|---|---|
| Не задан endpoint/model/key | Заполнить настройки и `.env`; секреты не вставлять в URL |
| 401/403 API модели | Проверить действительный ключ, доступ к модели и точный endpoint |
| 400 API модели | Сверить `token_parameter`, `json_mode`, поддержку параметров |
| Все поиски неудачны | Прочитать `searches/.../report.json`; подождать либо импортировать реальные записи |
| Кандидатов больше лимита | Сузить scope/query/годы или осознанно повысить лимит |
| Источник недоступен/не PDF | Дать локальный файл; не обходить paywall, auth или challenge |
| Не установлен pypdf | Установить PDF extra; не переходить молча на выдуманное содержание |
| Цитата не найдена | Проверить сырой ответ и сегмент; исправить источник/промпт, затем повторить этап |
| JSON невалиден/ответ обрезан | Скорректировать модель/бюджет; сырая ошибка сохранена, успешной карточки нет |
| Input слишком длинный | Сузить корпус, изменить число отбираемых тезисов или подтвердить больший контекст |
| Состояние устарело | Выполнить названный этап, затем последующие; это защита от смешения версий |
| Quality gate заблокирован | Устранить ошибки; не удалять проверку ради экспорта |
| В audit есть замечания | Сверить конкретные тезисы/источники и уточнить критерии или промпт; автоматической правки научных утверждений нет |

## Статус реализации

В комплекте есть код, локальные проверки механических инвариантов и документация. **Реальные обзоры не генерировались, живые поисковые/модельные интеграции не проверялись.** Качество конкретной модели, API-совместимость, доступность PDF и научная полнота остаются неопределёнными до первого разрешённого запуска. Отчёт о выполненных в этой сессии офлайн-проверках — в `docs/verification.md`.

## Общие приватные настройки и выпуск

`library/model.toml` с `[model]` накладывает параметры на модель каждой темы. Секрет хранится только в `.env` или shell environment. Для индивидуальных моделей удалите общий файл и настройте темы отдельно. В публичном интерфейсе настроек нет.

`maintain` читает `.env` из родительского каталога библиотеки; обычные команды темы — её `.env`, затем текущий working directory, если не указан `--env`. Shell-переменные имеют приоритет. Запускайте команды из корня проекта.

Одноразовый приватный мониторинг: `maintain --library library`; платная подготовка черновиков требует `--generate`. Цикл `watch --interval-hours 168` работает, пока процесс запущен и машина не спит. Служба не установлена. Интервал — частота попыток, не обещание публикации. После ошибок смотрите `library/maintenance.json` и журналы тем; наличие прошлого обзора не доказывает успех нового поиска.

Для местного выпуска нужны существующий snapshot, проверка редактора и заметка: `release --library library --topic safety --snapshot '<ID>' --reviewed --note 'Что изменилось и почему'`. Затем `build-site --library library --destination site`. В интернет отправляется только `site/`. Эти команды не выполняют upload/deploy.

Год `review.year_to`, критерии, max_candidates и max_papers не увеличиваются тайно. Пересматривайте их при росте корпуса. В конфигурации `updates.refresh_metadata_days` остаётся рекомендацией и не создаёт отдельного задания обновления метаданных.
