# Когда обзор можно считать комплексным

Количество ссылок само по себе не определяет качество. Четыре работы на широкую зрелую тему недостаточны для заявленного охвата, но и сотни поисковых совпадений не заменяют обзор.

## Проверяемые требования

1. **Границы и вопросы.** Указать аудиторию, исходные знания, объект исследования, период и исключения. Большая категория AI research разбивается на несколько обозримых вопросов.
2. **Покрытие подходов.** Найти ранние ключевые работы, основные семейства методов, последующие улучшения, независимые оценки и ограничения. Проверять пробелы по семействам и вопросам, а не добирать число ссылок до квоты.
3. **Полнотекстовый отбор.** Аннотация помогает выбрать кандидатов; содержательные выводы извлекаются из доступного полного текста. Сохраняются исключения, дубликаты, недоступные работы и причины решений.
4. **Матрица свидетельств.** Для каждого важного тезиса — источник и точное место, экспериментальные условия, baseline, метрика, ограничения и тип утверждения. Для ускорения нельзя смешивать latency/throughput, GPU и batch; для safety — разные модели угроз; для robotics — разные embodiment и условия переноса.
5. **Сопоставление.** Объяснить, где работы согласуются, где спорят и сравнимы ли их условия. Разделить авторский результат, гипотезу и редакторскую интерпретацию. Наличие настоящей цитаты не доказывает логическое следование вывода.
6. **Читательский маршрут.** Дать краткую картину, определения, карту подходов и путь углубления. Научные выводы должны вести к доказательствам; число карточек и длина текста не являются метрикой полезности.
7. **Версии и пробелы.** Показывать дату поиска, дату содержательного выпуска, неохваченные базы/подтемы и изменения конкретных выводов. Новая работа может подтвердить прежний результат и не требовать переписывания основы.

## Текущее состояние

Расширенный корпус теперь собирается воспроизводимым поиском; на сайте доступны годы, поисковые группы, фильтры и BibTeX. Это подготовка к комплексным обзорам. Первый обзор по 10 выбранным работам speculative decoding опубликован отдельно. Разбор всего поискового корпуса не выполнен.

Рабочий конвейер включает чтение, извлечение тезисов, синтез, критику, проверки и выпуск. Его код не проверялся живым запуском модели на большом корпусе. До 100 включённых работ — ресурсный потолок, не гарантия обработки любого корпуса: остаются ограничения контекста и общего числа обращений. Иерархический синтез по подвопросам и сохранение редакторских правок между такими частями требуют отдельной реализации/проверки. Нельзя объявлять комплексный обзор готовым по одному размеру библиографии.

## Передать корпус в существующий конвейер

Поиск сохраняет приватные библиографические записи с аннотациями в `library/.bibliography-search/imports/<topic>.json`. Например:

```bash
python3 -m review_forge import --project library/safety library/.bibliography-search/imports/safety.json
python3 -m review_forge plan --project library/safety
```

Эти две команды не вызывают модель. После настройки API отдельно запускается `screen` и последующие стадии; они могут расходовать средства. Кандидаты без доступной аннотации не получают выдуманную аннотацию. Исходные аннотации и кеши не публикуются.
