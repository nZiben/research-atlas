# Review Forge

Библиотека концептуальных обзоров AI research и отдельный приватный конвейер их подготовки. **Посетители только читают.** Поиск статей, модели, ключи и журналы остаются на компьютере владельца. На хостинг отправляются готовые статические файлы.

В комплекте десять разделов, расширенный поисковый корпус из 1669 уникальных публикаций и настройки узких стартовых тем. Первый обзор speculative decoding подготовлен по разделам 10 реальных полных текстов и хранится в `reviews/efficiency.json`. Остальные девять обзоров не опубликованы; API-конвейер генерации на реальном корпусе не проверен. Сайт публикуется через GitHub Pages; приватное расписание генерации не включено.

Подход вдохновлён [grokking-conceptual-review](https://github.com/kraidiky/grokking-conceptual-review). Это самостоятельная реализация; тексты, переводы и изображения примера не скопированы.

## Открыть библиотеку

Дважды нажмите **«Открыть библиотеку.command»** или из папки проекта выполните:

```bash
python3 -m review_forge serve --open
```

Команда офлайн собирает `site/` и открывает локальный просмотр на `http://127.0.0.1:8765`. Ключ не нужен. В интерфейсе только направления, обзор, источники, история и описание метода. Нет кнопок внешнего поиска, генерации, настроек модели или API для запуска задач. Остановка просмотра — `Ctrl+C`.

## Приватная настройка владельца

Python 3.11+, macOS/Linux. Для чтения сайта зависимости не нужны; PDF-конвейеру нужен `pypdf`.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[pdf]'
python -m review_forge init-library --library library
cp .env.example .env
chmod 600 .env
cp examples/model.toml library/model.toml
```

В `.env` заполните `REVIEW_API_KEY`. В `library/model.toml` задайте имя доступной модели и точный endpoint. Используется OpenAI-compatible Chat Completions; другой совместимый провайдер или localhost настраиваются теми же полями. Общие настройки `[model]` дополняют параметры каждой темы; секретов в TOML нет. Индивидуальные критерии, поисковые запросы, даты и бюджеты находятся в `library/<topic>/review.toml`.

Подписка на чат сама по себе не является API-ключом этого конвейера. Подробности — в [инструкции первого запуска](first-ten-reviews.md).

## Проверка новых работ и черновики

Следующие команды обращаются к внешним поисковым API. Без `--generate` модель не вызывается:

```bash
# Один проход, только поиск и очередь кандидатов.
python -m review_forge maintain --library library

# Повторять раз в неделю, пока процесс работает и компьютер не спит.
python -m review_forge watch --library library --interval-hours 168
```

После настройки модели можно разрешить платные вызовы, сначала для одной темы:

```bash
python -m review_forge maintain --library library --topic safety --generate

# Такой же приватный процесс с повторением по интервалу:
python -m review_forge watch --library library --generate --interval-hours 168
```

Цикл: ограниченный поиск → отбор → сравнение выбранного корпуса с последним черновиком → чтение/извлечение/синтез/критика только при изменении корпуса или исследовательских вопросов → новый приватный снимок. При неизменном корпусе синтез пропускается. Новые нерелевантные кандидаты сами по себе не требуют переписывать обзор. Кеш переиспользует только валидированные ответы.

Это **технический фильтр изменений**, а не доказанная оценка научной значимости. Полностью автоматического решения «новая работа меняет вывод X» пока нет. Последний отчёт — `library/maintenance.json`, подробности — в папках тем. Ошибка одной темы не останавливает попытки остальных; итоговый exit code при ошибках — 2. Ошибки отдельных поисковых провайдеров сохраняются как ограничение охвата.

`watch` не установлен как служба, не стартует при входе в систему и не переживает выключение компьютера. Для последующего системного планировщика используйте одноразовый `maintain`; планировщик в этой работе не настраивался. Проверяйте `year_to`: стартовые конфигурации ограничены 2026 годом. Лимит кандидатов потребует обслуживания по мере роста библиотеки.

## Выпуск проверенной версии и статический сайт

Черновик не появляется у читателей автоматически. Сначала проверьте выводы, доказательства, ограничения, замечания критика и возможность публикации цитат. Затем явно выберите реальный снимок:

```bash
python -m review_forge release --library library --topic safety \
  --snapshot '<ID проверенного снимка>' --reviewed \
  --note 'Какие выводы изменились и почему; проверенные источники'
python -m review_forge build-site --library library --destination site
```

`release` записывает локальный `library/releases.json`, не отправляет файлы в интернет. `build-site` читает только отмеченные в нём версии, проверяет их целостность и собирает публичный каталог. Сбой сборки сохраняет прежний сайт. Флаг `--reviewed` — заявление редактора, а не автоматическая научная экспертиза.

**На статический хостинг копируется только содержимое `site/`.** Python, база, ключи и оплачиваемые вызовы на хостинге не нужны. Приватные `library/`, `.env`, PDF, snapshot.json и журналы туда не копируются. Сайт использует относительные URL, поэтому может размещаться в подпапке. Его также можно проверить обычным HTTP-сервером:

```bash
python3 -m http.server 8765 --bind 127.0.0.1 --directory site
```

Для основного интерфейса нужен HTTP: прямой `file://` не гарантирует загрузку JSON. Отдельный экспорт HTML обзора самодостаточен.

## Произвольная тема и отдельные этапы

CLI не ограничен десятью категориями:

```bash
python -m review_forge init --topic 'Причинные проверки интерпретируемости LLM' --dir library/my-topic
python -m review_forge plan --project library/my-topic
# После настройки критериев и модели, с внешними запросами:
python -m review_forge run --project library/my-topic
```

Доступны `prepare`, `discover`, `import`, `decide`, `screen`, `ingest`, `extract`, `synthesize`, `audit`, `validate`, `export`, `compare`, `check-updates`. Полный список — `python -m review_forge --help`. `run --resume` пропускает повторный поиск. `ingest --refresh-sources` явно перечитывает источники. Публичная навигация сейчас поддерживает один выпущенный обзор на каждую из десяти категорий; произвольная тема экспортируется отдельно. Несколько обзоров внутри категории — следующее расширение структуры.

## Данные и пределы

`library/<topic>/` хранит `review.toml`, `decisions.json`, накопленные `candidates.json`, журнал поиска, отбор, оригиналы и сегменты `corpus/`, точные запросы/ответы модели без ключей, кеш, usage, синтез, аудит и снимки. Приватные экспорты включают HTML, Markdown, JSON, CSV, BibTeX и граф связей. Публичная сборка включает только разрешённые данные выпущенных версий, HTML и BibTeX.

Поиск arXiv/Semantic Scholar ограничен выдачей и не обеспечивает полноту литературы. Статьи можно импортировать вручную. PDF-парсер не понимает рисунки/сканы и может терять таблицы и формулы. Недоступные выбранные полные тексты по умолчанию блокируют сборку. Цитата проверяется по сохранённому сегменту; её совпадение не доказывает правильность вывода. Модельная критика также может ошибаться.

Ограничены число обращений и размеры контекста/вывода; гарантированного денежного потолка нет. Используйте лимит расходов у провайдера. Нативные несовместимые API, OCR, репликация экспериментов, автоматическая оценка прав и автоматический deploy не реализованы.

## Проверки кода

```bash
python3 -m unittest discover -s tests -v
python3 -m compileall -q review_forge
node --check review_forge/web/app.js
```

Офлайн-проверки кода не подтверждают научное качество: живой цикл с реальными публикациями и выбранной моделью ещё не запускался.

## Расширенный поиск

`python3 -m review_forge.bibliography` использует публичный `bibliography/search-plan.json`: несколько сортировок, ранние/свежие работы, оценку ограничений и предварительные тематические фильтры. Поиск не вызывает модель и не делает научный обзор. Результат — кандидаты с проверенными метаданными. Кеш остаётся приватным, а протокол поиска попадает в статическую сборку.

По умолчанию ресурсы отбора увеличены до 1000 кандидатов и до 100 включённых работ, выдача — до 100 на запрос. Это потолки, а не желательное число статей. Лимит 250 обращений модели и проверка размера контекста сохранены. Для большого корпуса возможна остановка до платного запроса; автоматический иерархический синтез большого обзора не реализован. Не обходите это молчаливым сокращением доказательств; разделяйте слишком широкую тему на согласованные подвопросы.
