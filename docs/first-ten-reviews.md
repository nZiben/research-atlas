# Что нужно для первых десяти обзоров

## Минимальный набор

1. **Ключ OpenAI Platform, доступ к выбранной модели и API-баланс.** Нужен для приватного автоматического конвейера. ID модели указывается в library/model.toml; модель должна поддерживать используемый Chat Completions-протокол. Ключ хранится в локальном .env, передавать его в чат не нужно.
2. **Интернет и доступные полные тексты.** Поиск arXiv и Semantic Scholar уже реализован. Отдельный платный поисковый API для старта не требуется. Semantic Scholar может ограничивать keyless-запросы; при фактическом ограничении понадобится его ключ либо другой доступный источник/ручной импорт. Недоступные PDF не заменяются выдуманным содержанием.
3. **Python 3.11+ и PDF-зависимость.** В папке проекта: `python3 -m pip install -e '.[pdf]'`, лучше внутри `.venv`. Для просмотра самого сайта PDF-пакет не нужен.
4. **Согласованный размер и бюджет генерации.** Сейчас каждая тема ограничена 25 включёнными работами и 250 вызовами модели за один запуск. Это технические ограничения, а не оценка стоимости в деньгах. Для большого запуска сначала стоит проверить одну узкую тему и увидеть реальный расход/качество.

Темы, вопросы и стартовые запросы для всех десяти направлений уже подготовлены. Дополнительные GPU, база данных, сервер в облаке и платный веб-поиск для первого прохода не нужны. Статьи, не попавшие в поисковые базы, можно импортировать из реальной библиографии; ограничения охвата остаются видимыми.

## Можно ли использовать то, что входит в подписку Codex

Для автоматических API-запросов приватного конвейера **подписка не заменяет Platform API-ключ и баланс**. Официальная документация различает вход с ChatGPT для доступа по подписке и вход с API-ключом для оплаты по использованию. API-вызовы тарифицируются через OpenAI Platform; API token prices отделены от subscription usage. [Аутентификация](https://learn.chatgpt.com/docs/auth), [тарифы и лимиты](https://learn.chatgpt.com/docs/pricing).

Второй вариант — готовить обзоры со мной непосредственно в этом чате и затем сохранять результаты для сайта. Такая работа использует доступ и лимиты подписки. Это другой рабочий процесс: сайт не получает универсальный API-ключ из входа в Codex, а нынешний автоматический конвейер не использует ваш OAuth-сеанс как подмену API.

Достаточно ли лимитов конкретной подписки для десяти подробных обзоров за один раз, заранее неизвестно: расход зависит от объёма статей, глубины разбора и выбранной модели. Подготовка по одной теме позволяет честно оценить масштаб. Прямой API также не гарантирует качество без проверки первоисточников и итоговых выводов.

## Публичный сайт и приватная подготовка

Посетитель видит только выпущенные материалы. Ключи и настройки вводятся владельцем в локальные `.env`/TOML, поиск и генерация запускаются CLI. `maintain`/`watch` готовят приватные кандидаты и черновики; `release` и `build-site` формируют статический выпуск после проверки. Публичный хостинг не принимает пользовательские генерации и не оплачивает модельные вызовы.

В этой работе первые десять обзоров не создавались. Живые поисковые/модельные вызовы новым конвейером и проверка научного качества не выполнялись.
