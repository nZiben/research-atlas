# Публикация и обновление

Публичный сайт: https://nziben.github.io/research-atlas/ . Репозиторий: https://github.com/nZiben/research-atlas .

## Обновить библиографию

1. Уточните `bibliography/search-plan.json` и выполните `python3 -m review_forge.bibliography`. Проверьте кандидатов, журнал отсева и усечения. Все записи остаются `metadata_only`.
2. Соберите сайт: `python3 -m review_forge build-site --library library --destination public`.
3. Проверьте изменения и выполните commit/push. Workflow `Publish library` развернёт только `public/` на GitHub Pages.

Поиск, ключи, PDF и модельные вычисления остаются на компьютере владельца. Workflow не выполняет поиск и не вызывает модели. Обновление сайта происходит при push в main, ручном запуске либо после успешной еженедельной проверки статей workflow `Refresh literature`.

## Выпустить обзор

Подготовьте приватный черновик и проверьте его выводы/доказательства. `release --reviewed --note ...` выбирает существующий снимок для выпуска; `build-site --destination public` добавляет его к статической сборке. Затем проверьте diff и отправьте только публичные файлы. `library/`, `.env`, исходные PDF и логи не коммитятся.

Сборка включает проверенную публичную библиографию до появления обзора. При выпуске источники обзора отображаются отдельно от дополнительного списка чтения. Дата поиска библиографии не является датой научной проверки или гарантией полноты.

## Проверки

```bash
python3 -m unittest discover -s tests -v
python3 -m compileall -q review_forge
node --check review_forge/web/app.js
python3 -m http.server 8765 --bind 127.0.0.1 --directory public
```

Существующие записи arXiv проверены сетевым запросом. Полный автоматический цикл с моделью на реальном корпусе пока не проверен. Первый обзор по прочитанным разделам источников выпущен отдельно, как описано ниже.


## Публикация без API-конвейера

Первый обзор хранится в явно публичном `reviews/efficiency.json`. Его формат, происхождение и ограничения описаны в [reviews/README.md](../reviews/README.md). Изменение этого файла и `build-site --library library --destination public` обновляют публикацию без вызова модели. Проверяйте доказательства перед commit/push: структурная валидация не заменяет научную проверку. Приватные черновики в `reviews/` не сохраняются.


## Автоматическое пополнение литературы

`.github/workflows/refresh.yml` запускается по понедельникам в 02:17 UTC (10:17 Asia/Hong_Kong), а также вручную в Actions → Refresh literature → Run workflow. GitHub может задержать расписание и при длительной неактивности публичного репозитория отключить его; состояние видно в Actions.

`python -m review_forge.refresh` сохраняет прежний корпус, ищет новые submissions и revised versions с семидневным перекрытием от последней успешной проверки. Пагинация продолжается до покрытия окна. При исчерпании лимита страниц, сетевой ошибке или неправильной выдаче watermark и опубликованный корпус не продвигаются. При большом backlog лимит можно увеличить через `--max-pages`. Это не устраняет границ исходных запросов и тематического фильтра.

Только реально возвращённые записи получают новую дату проверки метаданных; остальные сохраняют прежнюю. Новые статьи — `metadata_only` кандидаты, а не проверенные доказательства. Обзор остаётся на прочитанных версиях; более новая доступная версия показывается во вкладке источников. В публичном `data/discovery.json` видны итоги последней проверки; протокол запросов — в `data/search-method.json`. Сырые ответы остаются локально на runner и не коммитятся.

После тестов и сборки workflow коммитит только `bibliography/papers.json` и `public/`, затем напрямую вызывает reusable Pages workflow с SHA полученного коммита. Это необходимо: push через GITHUB_TOKEN не запускает обычный push workflow. PAT, ключ модели и отдельный сервер не нужны. Неудачный push из-за конкурирующего изменения завершается ошибкой; force push и обход защиты ветки не используются. Ошибка deploy оставляет последний успешно развёрнутый сайт; повторный запуск выполняется из Actions.

GitHub workflow не переписывает обзоры и не запускает платные модели. Для изменения научных выводов нужен последующий разбор полных текстов.
