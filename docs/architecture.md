# Архитектура и данные

## Границы проекта

Три части: приватная Python-библиотека/CLI владельца → локальный выпуск проверенных снимков → публичный статический сайт только для чтения. Модельные API и поиск не вызываются браузером посетителя. Нет аккаунтов, БД, публичного worker или хостинга генерации.

`serve` — только loopback-предпросмотр готовой сборки; он не загружает ключи и не запускает конвейер. Методы записи возвращают 405, старых API задач/настроек нет. В интернет можно отдавать `site/` обычным статическим сервером.

Модули:

| Модуль | Ответственность |
|---|---|
| `cli.py` | Команды, создание темы, запуск этапов, локальный каталог тем и serve |
| `server.py`, `web/` | Статический читатель и локальный сервер предпросмотра без API записи |
| `maintenance.py` | Приватный мониторинг и подготовка изменившихся черновиков |
| `publishing.py` | Редакторский manifest выпусков и отдельная публичная сборка |
| `config.py` | TOML, dotenv, проверка настроек и API endpoint |
| `sources.py` | Поиск, исходные ответы API, дедупликация, импорт, новые кандидаты |
| `http.py` | Лимиты загрузки, таймауты, GET retries, защита авторизации при redirects |
| `documents.py` | PDF/TXT/Markdown → сегменты с локаторами, версии и хеши |
| `model.py` | Совместимый Chat Completions API, сохранение запросов, проверенный кеш, бюджет |
| `prompts.py` | Явные версии инструкций для каждой стадии |
| `evidence.py` | Проверка формы данных, цитат, ID и ссылок |
| `pipeline.py` | Отбор, извлечение, компрессия тезисов, синтез, критика, quality gate, snapshots |
| `export.py` | Markdown, HTML, JSON, graph, CSV, BibTeX без полного исходного текста |

CLI вызывает обычные Python-функции под блокировкой темы. Браузер делает только GET к готовым JSON и ресурсам. `watch` запускает `maintain` с интервалом; служба и системное расписание не установлены.

## Сущности

**Paper.** Стабильный локальный ID, название, авторы, DOI/arXiv, год, ссылки, происхождение метаданных. Дедупликация использует нормализованные идентификаторы и точное нормализованное название. Это не нечёткий bibliographic entity resolution: близкие названия могут остаться разными, а совпавшие названия — потребовать ручной проверки. Семейства очень близких работ и preprint/published версии с разными названиями автоматически не объединяются.

**Selection.** Для каждого кандидата: `core`, `external`, `exclude` или `deferred`, причина, приоритет и автор решения. `core` — прямое свидетельство по вопросу, `external` — контекст. Приоритет используется для ограничения объёма; он не измеряет истинность работы. `deferred` означает ограничение ресурсов, а не научное исключение. `decisions.json` хранит решения человека и имеет приоритет. Если после дедупликации изменился набор ID, неизвестный override блокируется до исправления.

**Document.** Источник, фактическая версия arXiv, SHA-256 оригинала и нормализованных сегментов, время получения, лицензия из метаданных или `unknown`, статус `full_text`/`abstract_only`. Оригиналы хранятся в `corpus/<id>/sources/<sha256>.<формат>`: новая версия не перезаписывает старые байты. Для PDF локатор — физическая страница PDF и номер выделенного текстового блока. Это не обещание совпадения с напечатанной нумерацией статьи или авторскими абзацами. Для текста — номер извлечённого абзаца. Очень длинные блоки дополнительно делятся; версия и хеш фиксируют конкретную сериализацию.

**Claim.** Один ограниченный тезис: `empirical`, `theoretical`, `hypothesis` или `interpretation`; условия, авторские ограничения, ярлыки понятий, короткие точные цитаты с ID сегментов. ID вычисляется из статьи, хеша документа и содержания тезиса. Повторная формулировка либо новая сериализация источника могут дать новый ID; изменение ID само по себе не является новым научным результатом.

**Concept.** Каноническое имя, aliases, определение, позиции работ, расхождения. Каждое содержательное высказывание адресует существующие claims. Связи между понятиями также требуют свидетельств. Модель может по-разному канонизировать понятия между генерациями; сравнение ID не решает автоматически задачу выравнивания онтологий.

**Snapshot.** Неизменяемый JSON-снимок текущих источников, карточек, отобранных для синтеза тезисов, результата, настроек без ключей, статуса качества и списка изменений. Контрольная сумма проверяется при экспорте/сравнении. Это обнаружение случайного изменения, не цифровая подпись.

## Кеш, обновления и ошибки

Ключ ответа модели включает точные system/user messages, параметры API, endpoint и версию промпта. Авторизационный ключ не входит в кеш. Перед переиспользованием результат повторно проходит текущий validator.

Состояние отбора зависит от метаданных кандидатов, критериев, бюджета отбора, модели и ручных решений. Документы зависят от источника/версии, содержимого локального файла и параметров сегментации. Карточки зависят от документа, темы, роли работы, промптов, модели и параметров извлечения. Общий синтез зависит от выбранных тезисов и модели синтеза. Устаревшее состояние блокирует последующие этапы с указанием нужной команды. В run-логах и снимках сохраняются версии Python/pypdf, платформа и хеши реализации.

`check-updates` сравнивает новую выдачу с предыдущими кандидатами, а `pending_screening` — с последним отбором. Непросмотренная работа не исчезает из очереди только потому, что поиск повторён. Кандидатная библиография накопительная: изменение границ обзора требует повторного отбора, а не молчаливого удаления истории.

Нет удаления старых оригиналов/снимков для экономии места. Если источники большие, объём приватной библиотеки растёт; очистку следует делать осознанно после резервирования нужных версий. Большие скачивания ограничены 40 MB на документ в этой версии.

Ошибка чтения выбранного источника, неверная цитата, неизвестная ссылка, невалидный JSON, недостаток основных статей или устаревший синтез блокируют сборку. Ошибка одного поискового провайдера при успешном другом сохраняется как ограничение охвата. `run` прекращается при ошибке; уже завершённые запросы и этапы сохраняются. Успехом считается созданный проверяемый **черновик**, а не доказанная научная истинность.

## Публикация и интерфейс

`latest.json` указывает на последний **приватный черновик**. `library/releases.json` отдельно перечисляет выбранные редактором версии, дату выпуска, заметку об изменениях и контрольную сумму. Сам по себе снимок не становится публичным. `release --reviewed --note ...` фиксирует решение владельца; это не научная сертификация.

`build-site` сверяет выпущенные снимки, подготавливает новый каталог и заменяет предыдущую сборку только после успеха:

```text
site/
  index.html, app.js, style.css, mark.svg
  data/library.json                    # десять категорий, даты выпусков
  data/topics/<id>.json                # текущий обзор, источники, история
  data/reviews/<topic>/<snapshot>.json # только публичные поля версии
  exports/<topic>/<snapshot>/index.html
  exports/<topic>/<snapshot>/references.bib
  site-manifest.json                  # список файлов и хеши
```

Из публичного JSON исключены config, полные исходники, локальные пути, точные API-запросы/ответы и внутренние журналы. Короткие цитаты и библиографические метаданные остаются: их допустимость проверяет редактор. Самодостаточный HTML формируется с экранированием текста и допустимыми web-ссылками. Нельзя раздавать корень проекта или `library/` вместо `site/`.

Приватный экспорт по-прежнему содержит `review.json`, `graph.json`, CSV, Markdown и methodology. `catalog` — приватный технический индекс, не источник публичной навигации. Статический читатель отображает явно опубликованные снимки из manifest либо исходные публикации из `reviews/<topic>.json`. Если нет ни одного вида выпуска, показывает планируемые вопросы и доступную библиографию. Отсутствующий выпуск не подменяется последним черновиком.

## Частное обновление

`maintain` по умолчанию выполняет только discovery. При `--generate` сначала проверяет наличие настроек, проводит отбор и сравнивает выбранные статьи/версии и вопросы с последним снимком. Неизменный корпус пропускает последующие дорогие этапы. Изменившийся проходит ingest → extract → synthesize → audit → snapshot → приватный export. Публичный manifest при этом не меняется.

Это сравнение корпуса, а не семантический анализ важности. Изменение модели/промпта само по себе не обещает пересборку неизменного корпуса: для принудительного обновления используйте отдельные команды/`run`. Изменённые байты локального файла без изменения метаданных также требуют явного перечитывания. Перечитывание изменяемого удалённого URL без сигнала о версии не выполняется автоматически.

`library/maintenance.json` хранит последний отчёт; логи темы — конкретные поиски/запросы. Отказы отдельных тем фиксируются, остальные продолжаются. Успех одной поисковой базы при отказе другой означает неполный поиск, а не доказанную актуальность. Для мониторинга по всему году нужно обслуживать диапазон дат; текущие пресеты заканчиваются 2026 годом.

## Что специально не реализовано

Нативные API несовместимых провайдеров; прямые коннекторы OpenReview/CVF/ACL; рекурсивный snowballing по графу цитирований; OCR и vision extraction; автоматический полный перевод; автоматическая классификация прав; научная репликация экспериментов; системная установка scheduler; семантическая оценка влияния новой статьи на конкретный вывод; совместное редактирование; многопользовательская аутентификация и deploy. Эти функции не замещены имитациями.

Наиболее полезные следующие расширения: импорт bibliographic records из нужного вам источника, разбор таблиц/формул с проверкой, ручная редактура тезисов с журналом изменений в интерфейсе. Подключать их стоит после оценки качества первого реального черновика на узкой знакомой теме.

## Начальная публичная библиография

`bibliography/papers.json` хранит метаданные расширенного корпуса кандидатов по десяти вопросам, дату поиска, реальные версии arXiv и происхождение данных. `build-site` добавляет эти записи как `reading_list` с покрытием `metadata_only`. Их наличие не создаёт обзор, научные тезисы или редакторский выпуск. Дополнительная библиография отделена от источников выпущенного обзора явной меткой. Приватные поля отбрасываются по allowlist.

Для GitHub Pages собирается и коммитится `public/`. Workflow разворачивает только этот каталог. Поиск и вызовы моделей в Actions не запускаются.

`bibliography.py` выполняет ограниченный воспроизводимый поиск по `search-plan.json`; сохраняет все прошедшие предварительный фильтр записи, явные seeds, журнал отсечений и усечение. `discovery_groups` — происхождение из поисковой стратегии, не экспертная классификация методов или научной значимости. Статический читатель показывает фактический охват по годам, локальные фильтры и страницы списка; ни один из этих контролов не запускает внешний поиск.


## Публикации по прочитанным источникам

`editorial.py` проверяет явно публичные `reviews/<topic>.json`: версии источников, ссылки на разделы, соответствие тезисов и сравнительной таблицы, бюджет цитат и границы метаданных. Такой выпуск имеет вид `editorial_review`, не выдаётся за результат модельного конвейера и не записывается в приватный `releases.json`. Для темы с выпущенным модельным снимком приоритет у него. Сейчас в редакционной папке хранится одна версия на тему; история нескольких таких версий ещё не реализована.

Интерфейс поддерживает краткий и подробный режимы, таблицу условий и дерево подтем. `related.html` содержит ссылки на родственные проекты и сравнение их документированных границ с нашими задачами. Это обычные статические файлы без серверной генерации.


## Пополнение библиографии на GitHub

`refresh.py` выполняет атомарное накопительное discovery, отдельно от source-based обзоров и приватной модельной генерации. Проверяется Atom feed, пагинация, повтор страницы, версии, даты и ограничение числа страниц. При сбое прежний corpus и watermark сохраняются. `last_update` содержит added/updated IDs; при сборке экспортируются только публичные поля отчёта.

GitHub Actions запускает тесты, refresh, build-site и ограниченный commit. Pages вызывается reusable workflow по фактическому SHA после push. Разрешение contents:write ограничено discovery job; deploy получает pages:write и id-token:write. Научное содержание reviews/ не входит в автоматический commit.
